# notion-archive

읽을 사람은 6개월 뒤의 본인 하나. 검색해 들어와 3초 안에 판단하고 닫는다.
ChatGPT/Codex 쪽 동명 스킬과 같은 형식을 쓴다 — 임의로 바꾸지 않는다.

## 0. 먼저 읽는다

저장 전에 두 가지를 조회한다.

1. `🗂️ ChatGPT 아카이브`의 **현재 스키마.** 아래 3절 표에 있어도 스키마에 없는 속성은 넣지 않고, 마무리 보고에 한 줄 적는다.
2. 노션의 `노션 저장 공통 규칙` 페이지(아카이브 안). 이 스킬과 충돌하면 **노션 쪽 최신 규칙을 따르고** 충돌 사실을 보고한다.

## 1. 어디에 저장하나

1. **사용자가 지정한 곳이 있으면 거기.** ("○○ 페이지 밑에", "△△ DB에")
2. 지정이 없으면 **항상** `🗂️ ChatGPT 아카이브` DB. 주제(여행·업무 등)를 이유로 다른 페이지에 넣지 않는다.
   (`data_source_id: c61e2921-0d06-4a02-a7af-75e9ba4d2858` · `database_id: 15718cd0-d403-46f5-9a59-2ae756dab9df` — 참고값. 못 찾으면 이름으로 검색한다)
3. 접근·권한 오류가 나면 실패한 단계를 알리고 멈춘다. 동의 없이 다른 위치에 대신 저장하지 않는다.

**새로 만들기 전에 같은 목적의 문서를 찾는다.**
`출처 URL` 일치, 그리고 제목·키워드 검색으로 후보를 찾는다. 제목이 비슷하다는 것만으로 중복이라 판단하지 않는다 — 후보를 열어 읽는다.

- 같은 목적의 문서가 있으면: 사용자가 "업데이트"라고 했으면 그 원본의 필요한 부분만 고친다. 아니면 갱신할지 새로 만들지 한 번 묻는다.
- 갱신할 때 기존의 사실·수치·조건·출처·미확인 표시를 지우지 않는다. 과거판이 필요하면 새 문서에 원본 링크를 남긴다.

공통: 페이지 **1개**, 원본 대화는 저장하지 않는다(정리본만).
그러므로 **결정적 수치·인용·조문은 원문 표현 그대로 + 출처.** 되돌아갈 길이 없다.

## 2. 본문 골격 (어디에 저장하든 동일)

```
> 🎯 결론        인용 블록 3줄 이내: 결론 / 쓸모·판단 기준 / 기준일·검증
## 📌 핵심 3~5   한 줄씩. 여기까지가 "3초 독자"의 영역
## 🧩 <소제목>    소결론 → 왜 → 근거·수치(출처). 배경으로 열지 않는다
                 소제목은 내용을 담아 쓴다: "2. 세부사항" ❌ / "인출 조건 — IRP만 예외" ⭕
## 📊 비교        선택지가 둘 이상이면 산문 대신 표 (3~4열)
## ⚠️ 확인 필요   항목 / 왜 미확인인가 / 확인 방법
## ➡️ 다음 수     없으면 생략
## 🔗 출처        [제목](URL) — 발행처(날짜)
```

- **검증 표기는 결론 블록 3번째 줄에 글자로 적는다.** `기준일 2026-09-04 · 검증: 확인됨 / 일부 미확인 / 미확인` 중 하나. DB에는 검증 속성이 없으므로 여기가 유일한 자리다.
- AI가 읽고 요약했다는 것만으로 `확인됨`이라 적지 않는다.
- 되풀이 요약을 아래에 붙이지 않는다. 결론은 이미 맨 위에 있다.
- 이모지는 제목 앞에만. 길이는 내용이 정한다.
- 「확인 필요」는 항목이 있으면 반드시 넣고, 하나도 없으면 절 자체를 뺀다.

**제목은 `주제 — 결론 조각`.** 결론이 제목에 없으면 열어봐야 알고, 여는 순간 진 것이다.

## 3. 메타는 목적지에 맞춘다

**아카이브 DB에 저장할 때** — 속성 이름 그대로:

| 속성 | 타입 | 값 |
| :--- | :--- | :--- |
| `제목` | title | 위 제목 규칙 |
| `한 줄 결론` | text | 목록 뷰에서 스캔할 한 문장 — DB 차원의 BLUF. **비우지 않는다** |
| `주제 태그` | multi_select | 업무·행정 / 법령·판례 / 투자·경제 / 여행 / AI·도구 / 학습·개념 / 생활·소비 / 건강 / 기타 **중에서만** |
| `정리일` | date | `date:정리일:start` (날짜만, `is_datetime: 0`) |
| `키워드` | text | 미래의 내가 검색창에 칠 말 (동의어·영문 포함) |
| `출처 URL` | url | 있으면 기입. 중복 후보를 찾는 키 중 하나 |
| `정리 상태` | select | 결론까지 정리한 자료는 `활용`, 조사 중간·판단 전 메모는 `수집`. 새 페이지에 `보관`은 쓰지 않는다 |
| `연결 프로젝트` | relation | `🎯 프로젝트 관리`에서 진행 중인 프로젝트에 **명백히** 속할 때만 연결. 애매하면 비운다. 프로젝트 카드를 새로 만들지 않는다 |

- `선택`(폐기 표시) 속성은 건드리지 않는다.
- `정리 상태`와 검증은 별개다. `활용`이어도 일부 미확인일 수 있다.

**다른 DB에 저장할 때** — 그 DB의 스키마에 맞춘다. 빈 칸을 억지로 채우지 않는다.

**DB가 아닌 일반 페이지로 저장할 때** — 속성이 없으므로 `한 줄 결론`이 갈 곳이 사라진다.
그러니 결론 블록 바로 아래에 메타 한 줄을 넣는다:
`기준일 2026-09-04 · 검증: 일부 미확인 · 키워드: ○○, △△`

## 4. 근거가 없을 때

지어내지 않는다. 자리를 비우고 「확인 필요」에 한 줄 적는다.
그럴듯한 숫자 한 개가 영구 기록이 되는 것 — 이 스킬의 유일한 치명적 실패다.

## 5. 노션 렌더 함정

- 표 앞뒤에 빈 줄 필수. 표 두 개를 붙이지 말 것(사이에 한 줄). 3~4열까지.
- 하이라이트·콜아웃 문법에 의존하지 않는다 — `⚠️ 확인 필요:`처럼 **라벨을 글자로** 박는다.
- 본문이 길면 나눠 적재한다.

## 6. 저장 후 다시 읽는다

페이지를 다시 조회해 확인한다. 확인한 범위만 보고한다.

- 부모가 의도한 위치(기본: `🗂️ ChatGPT 아카이브`)인가
- 본문이 마지막 절(🔗 출처)까지 들어갔는가
- `한 줄 결론`·`주제 태그`·`정리일`·`정리 상태`가 채워졌는가, 연결했다면 `연결 프로젝트`가 걸렸는가

## 7. 마무리

**저장한 위치**와 페이지 링크, 새로 만들었는지 갱신했는지, 그리고 「확인 필요」 항목만 보고한다. 본문을 채팅에 다시 늘어놓지 않는다.
