# notion-archive

읽을 사람은 6개월 뒤의 나 하나다. 그 사람은 맥락을 전부 잊었고, 같은 페이지를 세 번 다른 목적으로 연다.

| 여는 나 | 보는 곳 | 여기에 둘 것 |
| :--- | :--- | :--- |
| **훑는 나** — 목록·검색 결과 | 제목, `한 줄 결론`, 아이콘 | 주제 + 결론 조각 |
| **결정하는 나** — 페이지 첫 화면 | 결론 블록 → 맥락 줄 → 소제목 | BLUF, 육하원칙 맥락, 소제목마다 PREP |
| **검산하는 나** — 필요할 때만 | 토글, 출처 | 뺀 것, 계산, 원문, 작업 기록 |

층이 섞이면 셋 다 느려진다. 아래 규칙은 전부 이 세 층을 노션에 옮긴 것이다. (규칙마다의 연구 근거는 스킬 저장소의 `docs/notion-archive-research.md`에 있다. 유지보수용이라 저장할 때는 읽지 않아도 된다.)

이 파일이 기준본이다. ChatGPT/Codex 쪽 동명 스킬을 고칠 때는 이 파일에 맞춘다.

## 0. 순서

```
- [ ] 1. 규칙·스키마 읽기
- [ ] 2. 같은 목적 문서 찾기 → 갱신인지 신규인지
- [ ] 3. 문서 유형 고르기
- [ ] 4. 결론 블록과 맥락 줄부터 쓰기
- [ ] 5. 본문 PREP 블록 → 확인 필요 → 토글
- [ ] 6. 속성 채우기
- [ ] 7. 저장 → 다시 읽기 → 자가점검
- [ ] 8. 보고
```

## 1. 먼저 읽는다

1. `🗂️ ChatGPT 아카이브`의 **현재 스키마.** 아래 8절 표에 있어도 스키마에 없는 속성은 넣지 않고, 보고에 한 줄 적는다.
2. 노션의 `노션 저장 공통 규칙` 페이지(아카이브 안). 이 스킬과 충돌하면 **노션 쪽 최신 규칙을 따르고** 충돌 사실을 보고한다.

## 2. 어디에, 새로 쓸지 고칠지

**위치**
1. 사용자가 지정한 곳이 있으면 거기. ("○○ 페이지 밑에", "△△ DB에")
2. 지정이 없으면 **항상** `🗂️ ChatGPT 아카이브` DB. 주제를 이유로 다른 페이지에 넣지 않는다.
   (`data_source_id: c61e2921-0d06-4a02-a7af-75e9ba4d2858` · `database_id: 15718cd0-d403-46f5-9a59-2ae756dab9df` — 참고값. 못 찾으면 이름으로 검색한다)
3. 접근·권한 오류가 나면 실패한 단계를 알리고 멈춘다. 동의 없이 다른 위치에 대신 저장하지 않는다.

**중복 확인** — `출처 URL` 일치, 제목·키워드 검색으로 후보를 찾는다. 제목이 비슷하다는 것만으로 중복이라 판단하지 않고 후보를 열어 읽는다.

- 같은 목적의 문서가 있으면: 사용자가 "업데이트"라고 했으면 원본의 필요한 부분만 고친다. 아니면 갱신할지 새로 만들지 한 번 묻는다.
- 갱신할 때 기존의 사실·수치·조건·출처·미확인 표시를 지우지 않는다.
- **결론이 바뀌면 조용히 덮어쓰지 않는다.** 결론 블록에 `변경 2026-09-29 · 이전: ○○ → 바꾼 이유: △△` 한 줄을 남긴다. 반년 뒤의 내가 "예전엔 왜 다르게 판단했지"를 다시 조사하지 않게 하기 위해서다.

공통: 페이지 **1개**. 원본 대화는 저장하지 않고 정리본만 남긴다. 그러니 **결정적 수치·인용·조문은 원문 표현 그대로 + 출처.** 되돌아갈 길이 없다.

## 3. 유형을 고른다

내용을 먼저 읽고 가장 가까운 유형 하나를 큰 틀로 삼는다. 섞여 있으면 큰 틀 안에 다른 유형의 블록을 끼운다. 유형별 골격 예시는 [references/templates.md](references/templates.md)에 있다.

| 유형 | 결론 블록에 쓸 것 | 본문 흐름 | 특히 챙길 W |
| :--- | :--- | :--- | :--- |
| **비교·결정** | 고른 것(또는 기울어진 쪽)과 조건 | 판단 기준 → 후보별 PREP → 비교표 | 왜·얼마 |
| **방법·절차** | 가장 짧은 경로 한 줄 | 준비 → 번호 단계 → ※ 함정 → 완료 확인 | 어떻게·어디서 |
| **개념·학습** | 한 문장 정의 + 어디에 쓰나 | 정의 → 원리 → 예시 → 오해 | 무엇·왜 |
| **조사·현황** | 지금 상태 판단 | 쟁점별 PREP, 신뢰도 순 | 언제(기준일)·누가(출처) |
| **기록·회고** | 결과 + 다음에 바꿀 것 | 경과(시간순) → 원인 → 다음엔 | 언제·어디서·누가 |
| **목록·클리핑** | 무슨 목록인지 + 개수 | 묶음별 목록 | 없으면 생략 |

## 4. 결론 블록 — BLUF

페이지 맨 위, 제목 바로 아래. **결론 + 다음 행동 + 기한**이 BLUF다. 결론만 있으면 주장이고, 반년 뒤에 다시 여는 이유는 대개 "그래서 내가 뭘 언제 해야 했지"다.

```
<callout icon="🎯" color="green_bg">
	**추천: 알뜰폰 결합을 빼면 하이마트 1G+TV가 1순위 — 92만원 서면 확인이 조건.**
	다음 행동: 하이마트에 지급 주체·지급일 서면 요청 · 기한: 9/14(월) 접수 마감
	기준일 2026-09-05 · 검증: 일부 미확인
</callout>
```

- 첫 줄의 라벨로 판단의 주인을 밝힌다. **결정**(사용자가 정함) / **추천**(AI 제안, 사용자 미확정) / **미정**(다음 행동이 남음) / **정리**(판단이 필요 없는 자료). 반년 뒤에 AI의 추천을 내 결정으로 착각하면 안 된다.
- **기준일 ≠ 기한.** 기준일은 정보가 언제 시점인지, 기한은 내가 언제까지 움직여야 하는지다. 한 날짜로 뭉개지 않는다.
- 할 일이 없는 자료는 둘째 줄을 `쓸모: 여권 재발급 때 다시 볼 절차`처럼 쓴다. 없는 행동을 지어내지 않는다.
- 검증은 `확인됨 / 일부 미확인 / 미확인` 중 하나를 글자로 적는다. DB에 검증 속성이 없으므로 여기가 유일한 자리다. AI가 읽고 요약했다는 것만으로 `확인됨`이라 쓰지 않는다.
- 반드시 알아야 할 함정이 **하나** 있으면 바로 아래에 `<callout icon="⚠️" color="pink_bg">`로 한 줄 둔다. 둘 이상이면 콜아웃을 늘리지 말고 「확인 필요」로 보낸다.
- 결론을 아래에서 되풀이하지 않는다. 예외는 본문을 쓰다 결론에 조건이 붙어 달라졌을 때뿐이고, 그때는 결론 블록 자체를 고친다.

## 5. 맥락 줄 — 육하원칙을 자연스럽게

결론 블록 바로 아래에 회색 글자 한두 줄. 6개월 뒤의 나는 **누구 일이었는지, 어디 얘기였는지, 왜 이 조사를 했는지**부터 잊는다. 제목·결론 앞에 맥락이 있어야 본문이 읽힌다.

```
**맥락** 누가 동욱·진주 · 어디서 울산 서사 시티프라디움 · 왜 11월 입주, 1G 필수·TV 선택 · 얼마 3년 총액 기준 {color="gray"}
```

육하원칙은 빈칸 채우기 양식이 아니라 **빠진 맥락을 찾는 점검표**다. 그래서 한 표에 몰지 않고 원래 있어야 할 세 자리에 나눠 넣는다.

| W | 들어가는 자리 |
| :--- | :--- |
| 무엇을 · 어떻게 · 언제(기한) | 결론 블록 — 결론, 다음 행동, 기한 |
| 누가 · 어디서 · 왜 · 얼마 | 맥락 줄 — 이 문서가 누구의 어떤 상황인지 |
| 누가 · 언제 · 어디서 (근거의) | 본문 E — `KT 공식몰(2026-09-05 확인)`처럼 수치마다 발행처·시점 |

- 이 문서에 **의미 있는 W만** 쓴다. 개념 정리에 `어디서`를 억지로 넣지 않는다.
- 의미 있는데 모르는 W는 빼지 말고 `미확인`이라 쓴다. `없음`(알아봤더니 없음)과 `미확인`(안 알아봄)은 다르다.
- 돈이 걸린 문서는 `얼마`(총액·기준)를 넣는다. 한국 공문서 관행인 5W2H다.
- 라벨은 `누가·언제·어디서·왜·얼마·조건` 중에서 고르고, 한 문서 안에서 같은 이름을 끝까지 쓴다.

## 6. 본문 — 소제목마다 PREP

독자는 소제목만 징검다리처럼 밟고 내려간다. 그래서 **소제목 = 그 블록의 결론(P)** 이다.

- **P · 소제목:** 핵심 명사를 앞에 두고 결론을 담는다. `2. 세부사항` ❌ / `설치비 — 3사 모두 평일 3만6천원대` ⭕
- **R · 첫 문장:** 왜 그런지 한 문장.
- **E · 근거:** 수치·인용·조문을 원문 그대로, 발행처·날짜와 함께. 없으면 9절을 따른다.
- **P · 재진술:** 쓰지 않는다. 조건이 붙어 결론이 달라졌을 때만 블록 끝에 한 줄.

블록 순서와 모양:
- 결정에 영향이 큰 블록부터 둔다. 배경과 경위는 맨 뒤나 토글로 보낸다.
- 소제목끼리 겹치지 않고, 합치면 결론을 빠짐없이 받쳐야 한다(MECE).
- 소제목이 4개 이상이면 결론 블록 아래에 `## 📌 핵심` 3~5줄을 둔다. 각 줄은 아래 소제목의 P를 같은 순서로 요약한다.
- 선택지가 둘 이상이면 산문 대신 표를 쓴다(3~4열). 표 바로 위에 그 표의 결론을 한 줄 적는다.
- 이모지는 `##` 제목 앞에만 쓰고 본문 문장에는 넣지 않는다. 길이는 내용이 정한다.

### 확인 필요 — 펼쳐 둔다

미확인은 다음 행동을 막는 정보라서 토글에 숨기지 않는다. 항목이 있으면 본문 끝에 `## ⚠️ 확인 필요` 표(항목 / 왜 미확인인가 / 확인 방법)를 둔다. 하나도 없으면 절 자체를 뺀다.

## 7. 토글로 내리는 것 — 검산층

검산할 때만 필요한 것은 `<details>` 토글에 넣는다. 첫 화면을 짧게 유지하되 **지우지는 않는다.**

- **🗑️ 뺀 것** — 탈락 후보와 이유 한 줄. 지우면 반년 뒤에 같은 후보를 다시 조사한다.
- **🧮 계산·가정** — 식과 전제. 결론에 쓴 숫자는 본문에 두고, 검산 과정만 토글로 내린다.
- **📎 원문 발췌** — 조문·약관처럼 표현 자체가 중요한 긴 인용.
- **🧾 작업 기록** — 로컬 파일 경로, 조사 방법, 하지 않은 것. 6개월 뒤의 판단에는 쓰이지 않는 정보다.
- **🔗 출처** — `## 🔗 출처` 제목은 펼쳐 두고 목록은 `[제목](URL) — 발행처(날짜)`로 쓴다. 8개가 넘으면 발행처별 토글로 묶는다.

## 8. 속성 — 목적지에 맞춘다

**아카이브 DB에 저장할 때** — 속성 이름 그대로 쓴다.

| 속성 | 값 |
| :--- | :--- |
| `제목` | **`주제 — 결론 조각`.** 검색될 명사를 앞에 둔다. 결론이 제목에 없으면 열어봐야 알고, 여는 순간 진 것이다 |
| `한 줄 결론` | 결론 블록 첫 줄을 한 문장으로. 목록 뷰의 BLUF라서 **비우지 않는다** |
| `주제 태그` | 업무·행정 / 법령·판례 / 투자·경제 / 여행 / AI·도구 / 학습·개념 / 생활·소비 / 건강 / 기타 / 시스템 **중에서만.** `시스템`은 아카이브 운영 규칙·홈·가이드 같은 문서에만 쓴다 |
| `정리일` | 저장하거나 갱신한 날. `date:정리일:start`, 날짜만(`is_datetime: 0`) |
| `키워드` | 미래의 내가 검색창에 칠 말 5~15개. 동의어·영문·약어·고유명사·사람 이름을 섞는다. 사람마다 같은 대상을 다른 단어로 부른다 |
| `출처 URL` | 대표 출처 하나. 중복 후보를 찾는 키다 |
| `정리 상태` | 새 문서는 **`수집`** 이 기본이다. 사용자가 `활용`·`보관`을 말하면 그 값을 쓴다. 갱신할 때는 기존 값을 유지한다 |
| `연결 프로젝트` | `🎯 프로젝트 관리`의 진행 중 프로젝트에 **명백히** 속할 때만 연결한다. 애매하면 비우고, 프로젝트 카드를 새로 만들지 않는다 |

- 페이지 아이콘은 내용을 대표하는 이모지 하나. 목록에서 종류 표시로 쓰인다.
- `선택`(폐기 표시) 속성은 건드리지 않는다.
- `정리 상태`와 검증은 별개다. `활용`이어도 일부 미확인일 수 있다.

**다른 DB에 저장할 때** — 그 DB의 스키마에 맞춘다. 빈 칸을 억지로 채우지 않는다.

**DB가 아닌 일반 페이지로 저장할 때** — 속성이 없으므로 결론 블록 셋째 줄을 `기준일 2026-09-29 · 검증: 일부 미확인 · 키워드: ○○, △△`로 늘린다.

## 9. 근거가 없을 때 — E 슬롯 안전수칙

PREP의 E 자리는 숫자처럼 생긴 것을 요구한다. 그래서 빈 E를 채우려다 숫자를 지어내기 쉽다. 그럴듯한 숫자 하나가 영구 기록이 되는 것이 이 스킬의 유일한 치명적 실패다.

1. **E를 비우고 R로 쓴다.** 근거 없는 사례보다 정직한 논리가 낫다.
2. **「확인 필요」에 올리고 확인 방법을 적는다.**
3. **정성 근거로 대체하되 정성이라고 밝힌다.** `정량 자료 없음. 후기에서 반복된 표현은 ○○`

숫자에는 출처 성격을 붙인다. 원문에서 확인한 값은 그대로, 직접 계산한 값은 `계산:` + 식, 가정에 기댄 값은 `추정:` + 가정. 셋을 한 표에 섞으면 표 아래에 표시 규칙을 적는다.

## 10. 노션 렌더 — 최소 규칙

자세한 문법과 함정은 [references/notion-markdown.md](references/notion-markdown.md)에 있다. 저장 전에 이것만은 지킨다.

- 콜아웃·토글의 자식 줄은 **탭으로 들여쓴다.** 안 하면 밖으로 빠진다.
- 표는 `<table header-row="true">` 문법을 쓴다. 셀 안에는 글자만 넣는다.
- 다른 페이지를 가리킬 때는 `<mention-page url="…"/>`만 쓴다. **`<page url="…">`는 그 페이지를 이 페이지 밑으로 옮겨 버린다.**
- 인용 블록 하나에 여러 줄을 넣을 때는 줄바꿈 대신 `<br>`을 쓴다.
- 본문이 길면 나눠 적재하고, 적재한 뒤 끝까지 들어갔는지 확인한다.

## 11. 저장 후 다시 읽고 점검한다

페이지를 다시 조회해 확인하고, 확인한 범위만 보고한다. 하나라도 걸리면 고친 뒤 다시 읽는다.

1. 부모가 의도한 위치(기본: `🗂️ ChatGPT 아카이브`)인가. 본문이 마지막 절까지 들어갔는가
2. **제목과 `한 줄 결론`만 보고** 무엇에 대한 어떤 결론인지 알 수 있는가
3. 결론 블록에 결론(라벨 포함)·다음 행동 또는 쓸모·기한(있으면)·기준일·검증이 있는가
4. 맥락 줄에 반년 뒤 잊을 누가·어디서·왜가 있는가. 원문에 없는 W를 지어 넣지 않았는가
5. **소제목만 이어 읽어도** 결론을 받치는 논리가 이어지는가
6. 원문에 없는 숫자가 없는가. 계산·추정 표시가 붙었는가
7. 뺀 것과 미확인이 지워지지 않고 남았는가
8. `한 줄 결론`·`주제 태그`·`정리일`·`정리 상태`·`키워드`가 채워졌는가. 연결했다면 `연결 프로젝트`가 걸렸는가

## 12. 보고

**저장한 위치와 페이지 링크**, 새로 만들었는지 갱신했는지, 결론 라벨(결정/추천/미정/정리), 「확인 필요」 항목만 보고한다. 결론을 사용자 대신 판단했거나 다음 행동·기한을 유추해 채웠으면 그 사실을 한 줄로 밝힌다. 본문을 채팅에 다시 늘어놓지 않는다.

## 하지 말 것

- 배경·경위로 페이지를 시작하기 — 결론이 스크롤 아래로 밀린다
- 결론만 쓰고 다음 행동·기한 빼기 — BLUF의 반쪽이다
- 육하원칙 표를 통째로 만들어 빈칸을 채우기 — 해당 없는 W는 쓰지 않는다
- `2. 세부사항`처럼 내용 없는 소제목
- 빈 근거 자리를 그럴듯한 숫자로 채우기
- 탈락 후보·미확인 지우기
- 결론이 바뀌었는데 이전 결론을 흔적 없이 덮어쓰기
- AI 추천을 `결정`으로 적기
- 끝에 요약을 한 번 더 붙이기
